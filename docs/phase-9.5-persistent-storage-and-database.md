# Phase 9.5 — Persistent Cloud Storage & Database Foundation

Phase 9.5 establishes PostgreSQL as the durable, relational persistence foundation for Job Copilot runtime state (Jobs, Provenance, Recommendations, Applications, Append-Only Event Ledgers, Frozen Snapshots, Copilot Queue, and Source Health) while preserving locked-phase semantics, canonical candidate truth isolation, and local development compatibility.

---

## 1. Objective & Architecture Overview

The primary objective is transitioning ephemeral cloud container state to durable PostgreSQL storage without modifying existing business rules, Phase 4 scoring, Phase 8 event models, or Phase 9 prioritization.

## 2. Persistence Inventory & Data Classification

| Classification | Category | Files / Paths | Handling Strategy |
| :--- | :--- | :--- | :--- |
| **A. CANONICAL CONFIGURATION** | Targets, Sources & Strategies | `data/config/*.yaml`, `data/resume_strategies/*.yaml` | Kept in Git repo & container image. Immutable at runtime. |
| **B. CANONICAL CANDIDATE TRUTH** | Master Profile & Evidence | `data/candidate/master_profile.yaml`, `evidence.yaml` | Strictly isolated from DB & Git; injected at runtime via secure volume/env. |
| **C. RUNTIME STRUCTURED STATE** | Ingested Jobs, Apps & Queue | `data/jobs/`, `data/tracking/`, `data/copilot/` | **Persisted in PostgreSQL** (Jobs, Provenance, Apps, Events, Queue). |
| **D. GENERATED ARTIFACTS** | Resumes, PDFs, Screenshots | `data/applications/*/package/`, `data/downloads/` | Kept as filesystem files; metadata stored in DB; S3 object store in Phase 10. |
| **E. TEMPORARY DATA** | Playwright traces, cache files | `.pytest_cache/`, `data/downloads/` | Kept ephemeral. |

## 3. Database Schema Specification

The database schema is managed via Alembic migrations (`src/job_copilot/db/migrations/`):

### 1. `jobs`
- **Fields:** `id` (PK), `job_id` (Unique, Index), `canonical_url` (Index), `title`, `company`, `location`, `remote_status`, `employment_type`, `url`, `source`, `description`, `normalized_content_hash` (Index), `lifecycle_status` (Index), `duplicate_of`, `requirements` (JSON), `preferred_qualifications` (JSON), `technologies` (JSON), `years_experience`, `salary_min`, `salary_max`, `currency`, `posted_at`, `discovered_at`, `created_at`, `updated_at`.
- **Purpose:** Stores canonical normalized job records and supports Phase 5 URL/content-hash deduplication.

### 2. `job_provenance`
- **Fields:** `id` (PK), `job_id_ref` (FK -> `jobs.id`), `source_id`, `source_url`, `source_job_id`, `discovered_at`, `source_metadata` (JSON), `created_at`, `updated_at`.
- **Constraints:** `UniqueConstraint(job_id_ref, source_id, source_url)`.
- **Purpose:** Tracks multi-source discovery links for a single canonical job posting.

### 3. `recommendations`
- **Fields:** `id` (PK), `job_id_ref` (FK -> `jobs.id`), `job_id` (Unique, Index), `match_score`, `recommendation`, `priority_score` (Index), `priority_band`, `recommended_strategy`, `category_scores` (JSON), `explanation_summary`, `created_at`, `updated_at`.
- **Purpose:** Persists evaluation results and priority scores generated by the Phase 4/9 engine without recomputing logic.

### 4. `applications`
- **Fields:** `id` (PK), `application_id` (Unique, Index), `job_id_str` (Unique, Index), `job_id` (FK -> `jobs.id`, Unique), `company`, `role`, `canonical_job_url`, `source`, `status` (Index), `current_status_at`, `strategy_used`, `resume_strategy`, `match_score`, `recommendation`, `package_path`, `browser_session_id`, `user_notes` (JSON), `notes`, `discovered_at`, `recommended_at`, `prepared_at`, `applied_at`, `submitted_at`, `created_at`, `updated_at`.
- **Purpose:** Represents tracked job applications.

### 5. `application_events` (Phase 8 Append-Only Ledger)
- **Fields:** `id` (PK), `event_id` (Unique, Index), `application_id_ref` (FK -> `applications.id`), `application_id` (Index), `job_id` (Index), `event_type` (Index), `timestamp` (Index), `source`, `notes`, `metadata_json` (JSON), `created_at`.
- **Constraints:** `UniqueConstraint(event_id)`, `UniqueConstraint(application_id, event_type, timestamp)`.
- **Purpose:** Immutable append-only audit trail of lifecycle stage transitions. Current application status is synchronized from this ledger.

### 6. `application_snapshots` (Frozen Submission Records)
- **Fields:** `id` (PK), `application_id_ref` (FK -> `applications.id`), `application_id` (Unique, Index), `job_id`, `timestamp`, `resume_strategy`, `match_score`, `recommendation`, `technical_match`, `responsibility_match`, `seniority_match`, `professional_evidence_match`, `domain_match`, `preference_match`, `credential_match`, `job_source`, `resume_pdf_path`, `cover_letter_path`, `applied_via`.
- **Purpose:** Preserves exact match breakdown and strategy frozen at submission time.

### 7. `copilot_queue`
- **Fields:** `id` (PK), `job_id` (Unique), `priority_band`, `priority_score` (Index), `queue_status` (Index), `category_scores` (JSON), `reasons` (JSON), `user_notes` (JSON), `created_at`, `updated_at`.
- **Purpose:** Persists prioritized Copilot Opportunity Queue across restarts.

### 8. `source_health`
- **Fields:** `source_id` (PK), `name`, `state` (Index), `discovery_mode`, `requires_login`, `check_interval_minutes`, `last_checked_at`, `message`, `updated_at`.
- **Purpose:** Durable health reports for career portals (LinkedIn, Naukri, Wellfound, etc.).

## 5. Repository Abstraction & Dual-Persistence Architecture

To maintain zero breakage of existing code and tests:
- **Repository Layer:** [`src/job_copilot/repositories/`](file:///Users/Hp/Apply-Agent/src/job_copilot/repositories/)
  - `JobRepository`: Database CRUD, multi-source provenance, and recommendation records.
  - `ApplicationRepository`: Application entity, append-only event ledger, submission snapshots.
  - `CopilotRepository`: Copilot queue state and source health tracking.
  - `CandidateRepository`: Canonical candidate truth manager (filesystem YAML).
- **Filesystem Compatibility:** Existing stores (`JobStore`, `TrackingStore`, `CopilotQueueStore`) remain intact and supported for local workflows.
- **Runtime Migrator:** [`src/job_copilot/db/migrator.py`](file:///Users/Hp/Apply-Agent/src/job_copilot/db/migrator.py) provides explicit, idempotent migration from filesystem state to PostgreSQL.

## 7. Render Cloud Database Configuration

Configured in [`render.yaml`](file:///Users/Hp/Apply-Agent/render.yaml):
- Defines managed PostgreSQL instance: `job-copilot-postgres`
- Injects database connection string dynamically into `job-copilot-api` web service via `fromDatabase: { name: job-copilot-postgres, property: connectionString }`
- **Zero hardcoded credentials** in source code or repository.

---

## 8. Database Health & Readiness Endpoints

- **`GET /health`**: Lightweight liveness probe (returns `{"status": "ok"}`).
- **`GET /ready`**: Readiness probe executing `SELECT 1` on the active database connection. Returns `200 OK` with `{"status": "ready", "database": "connected"}` or `503 Service Unavailable` if database is unreachable.

---

## 9. Security & URL Sanitization

- **Credential Redaction:** `sanitize_database_url()` masks username/password in logs (e.g. `postgresql://user:***@host:5432/db`).
- **Connection Pool Hardening:** Configured with `pool_pre_ping=True`, `pool_size=10`, `max_overflow=20`, `pool_recycle=300`.
- **Secret Scanner:** Verified clean (`0` exposed secrets).

---

## 10. Backup and Recovery Requirements

- **Production Strategy:** Render automated daily PostgreSQL backups with 7-day retention.
- **Disaster Recovery:** Point-in-time restore from Render dashboard.
- **Rollback:** Versioned Alembic downgrade support (`downgrade_migrations("base")`).

---

## 11. Known Limitations & Future Milestones

1. **Object Storage (Phase 10):** Large binary artifacts (PDF resumes, cover letters, screenshots) remain on filesystem; Phase 10 will introduce S3/GCS object storage reference architecture.
2. **Authenticated Cloud Workers (Phase 10):** Dedicated browser workers with secure session persistence remain planned for Phase 10.
3. **Candidate Truth Editing:** Canonical candidate truth remains file-based to guarantee single-source-of-truth immutability.
